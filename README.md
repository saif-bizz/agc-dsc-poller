# DSC Poller

A small GitHub Actions cron job that polls a Gallabox WhatsApp inbox for
unassigned conversations, drafts a reply via [`claude-code-action`][cca],
runs deterministic QC checks, and either sends the reply (live mode) or
posts the draft to a Telegram review channel (dry-run mode).

The Claude Code agent is named "Sara". She has Bash + file IO only — every
external API call (Gallabox, Shopify, Telegram, Cloudflare KV) goes through
the small Python helpers in `src/`.

[cca]: https://github.com/anthropics/claude-code-action

## Required GitHub Secrets

Set these at `Settings → Secrets and variables → Actions → New repository
secret`. Total: 17. Only `CLAUDE_CODE_OAUTH_TOKEN` is genuinely new — the
rest already exist in the operator's stack.

| # | Name | Purpose |
|---|---|---|
| 1 | `CLAUDE_CODE_OAUTH_TOKEN` | Auth for `claude-code-action`, generated by `/install-github-app` against a Claude Max subscription |
| 2 | `GALLABOX_API_KEY` | Gallabox API auth |
| 3 | `GALLABOX_API_SECRET` | Gallabox API auth |
| 4 | `GALLABOX_ACCOUNT_ID` | Account scope |
| 5 | `GALLABOX_CHANNEL_ID` | WhatsApp channel scope |
| 6 | `SHOPIFY_STORE` | e.g. `your-shop.myshopify.com` |
| 7 | `SHOPIFY_ADMIN_TOKEN` | Admin GraphQL access |
| 8 | `TELEGRAM_BOT_TOKEN` | Bot for floor-team + review channels |
| 9 | `TELEGRAM_CHAT_ID` | Floor-team escalation channel |
| 10 | `TELEGRAM_REVIEW_CHAT_ID` | Reviewer-only channel (dry-run posts) |
| 11 | `CF_API_TOKEN` | Cloudflare API token with `Workers KV Storage:Edit` |
| 12 | `CF_ACCOUNT_ID` | Cloudflare account id |
| 13 | `CF_KV_NAMESPACE_ID` | KV namespace id for the audit log |
| 14 | `ESCALATION_USER_ID` | Gallabox userId to assign escalated threads to |
| 15 | `ESCALATION_AOV_THRESHOLD` | Numeric order-value above which Sara hands off to floor team |
| 16 | `DRY_RUN` | `true` (default at deploy time) or `false` |
| 17 | `MAX_THREADS_PER_TICK` | `10` recommended |

## Local development

The helpers run anywhere with Python 3.12+. Use [`uv`][uv] for the venv,
or stdlib `venv`.

```bash
uv venv
uv pip install -r requirements.txt   # currently empty — helpers are stdlib-only
cp .env.example .env
# fill in real values in .env (DO NOT COMMIT — .env is gitignored)

set -a; source .env; set +a

# smoke tests
python src/gallabox.py list_open_unassigned --limit 5
python src/filters.py classify "do you have ficus in 14 inch"
python src/qc.py pre_check "i want refund my order is dead"

# DRY_RUN=true (default in .env.example) — no customer messages will be sent
python src/gallabox.py send 67abc 971501234567 "hello world"   # logs DRY_RUN
```

[uv]: https://github.com/astral-sh/uv

## Workflow trigger

- **Cron**: `*/5 * * * *` (every 5 minutes). Edit
  `.github/workflows/poll.yml` to widen the cadence if you hit free-tier
  caps.
- **Manual**: `Actions → DSC Poller → Run workflow`. There is an optional
  `dry_run_override` input that lets you run a one-off live (or dry) poll
  without changing the repo secret.
- **Concurrency**: only one run at a time. If a run is still going when
  the cron fires, the new run is queued (not cancelled).
- **Job timeout**: 4 minutes — ensures a hung run cannot block the next
  cron boundary.

## Cutover (one-time, when adopting this repo for the first time)

If you are migrating from a prior local poller and/or a prior Cloudflare
worker that did the same job, here is the order:

1. Set all 16 GitHub secrets, with `DRY_RUN=true`.
2. Trigger one manual `workflow_dispatch` run; verify it goes green and a
   draft lands in the Telegram review channel.
3. Wait for one cron `*/5` boundary; verify it fires automatically.
4. Run for 24 hours in dry-run. Spot-check the drafts. Fix
   `prompt/sara-system.md` or `prompt/brand-snippet.md` if anything is
   off-brand.
5. Once you accept ≥90% of drafts, flip `DRY_RUN=false` and re-trigger.
6. Decommission whatever was sending replies before (kill the local
   /loop, `wrangler delete` the prior worker, etc.).
